01

安装 Skill

目标：让本地 AI 工具找到并读取三个练习技能。

按顺序操作

  1. 打开本地 AI 工具准备好 Codex、Claude Code，或其他能操作本地文件并支持 Skill 的 AI 工具。先完成工具安装和登录。
  2. 选择练习文件夹在电脑上新建「AI-PO练习」文件夹，并在 AI 工具中将它打开为当前项目。
  3. 发送安装提示词复制本节的安装提示词。要安装到其他位置，可使用下方「指定文件夹」版本。
  4. 检查安装结果确认三个 Skill 各自有 SKILL.md，相关资源也已保留。再发送验证提示词。

02

定义问题

目标：先由团队写出具体问题与现有替代方案。讨论 8 分钟。

按顺序操作

  1. 选一个产品或服务确定谁在什么情境下使用它，先选团队熟悉的对象。
  2. 用简短文字写问题写出遇到的困难与影响。例如「同事反复追问进度」，而非「缺一个看板」。
  3. 列出现有替代方案一起头脑风暴，尽量列全目前使用的系统、表格、邮件、电话或人工做法。
  4. 保存并分享初稿填好问题记录表，保留团队原话。暂时不确定的内容标为「假设」，下一步交给 AI 探索。
这一步先由你和团队讨论，不需要调用 Skill。
问题记录表 · 复制到笔记中填写
产品或服务：［名称］
目标使用者：［谁］
使用情境：［什么时候、要完成什么事］

问题（Problem）：
［遇到什么困难，造成什么影响］

现有替代方案（Existing Alternatives）：
［现在用什么工具、流程或人工做法处理］

尚未确认：［目前只是猜测的部分］
授信系统示例 · 练习情境，待验证
目标使用者：分行与授信中心的业务、征信及审查人员。
问题：进度不透明，反复录入和查询，跨部门补材料慢。
现有替代方案：结合现有授信系统、Excel、邮件和电话跟进。

本步产出一份问题初稿与现有替代方案清单，团队能简短说明。

03

SKILL / initial-problem-discovery

问题探索

目标：找出遗漏的问题，分清已知信息与待验证假设。

按顺序操作

  1. 贴入上一步的记录打开已安装 Skill 的项目，复制本节提示词，贴入问题记录。
  2. 回答 AI 的追问根据团队观察或目前判断回答。不知道时直接说「目前不确定，请标为假设」。
  3. 核对摘要检查使用者、情境、问题和现有做法。有误就修正，正确再请 AI 整理初稿。
  4. 由团队决定保留什么删除不符合实际的推测，保存问题、现有替代方案与待验证事项。
AI 提出的新角度是探索线索。没有依据的内容，继续保留「待验证」标记。
问题探索提示词
请使用已安装的 initial-problem-discovery Skill，帮我检查还有哪些问题没考虑到。

请区分已知信息、推论与待验证假设，不编造客户反馈或数字。

2. 现有替代方案（Existing Alternatives）

本步产出团队确认的问题与现有做法，以及需要向谁验证哪些假设。

04

SKILL / value-proposition

愿景与价值主张

目标：说清楚为谁、解决什么问题，以及与现有做法的差异。

按顺序操作

  1. 先写七行初稿根据问题探索结果，填写本节的七行模板。聚焦一个主要客群。
  2. 让 Skill 检查并优化发送下方提示词，附上问题探索结果与七行初稿。
  3. 核对价值与差异回答追问并确认摘要。检查产品能力、比较对象和差异有没有依据。
  4. 读给组员听确认别人能用一两句话复述。保存七行版本，并保留待验证事项。
授信协作平台 · 愿景草案，能力与效果待验证
对于业务量大、跨部门交接频繁的分行与授信中心人员，
他们需要掌握授信进度和待补材料，减少录入、查询与催件时间，
企业授信工作平台
是一种整合进度、材料与操作流程的协作平台，
能够帮助同事掌握业务状态、改善交接并及早发现流程瓶颈，
不同于现有授信系统、Excel、邮件和电话分头跟进的做法，
我们的产品拟用看板集中展示进度和待补材料，并逐步实现数据自动填充与审核校验，让同事有更多时间审查业务。
七行模板 · 先填一版
对于［目标客户］，
他们［有某项困扰、需求或期待］，
［产品或服务名称］
是一种［概括描述］，
能够［解决关键问题的能力］，
不同于［替代产品、服务或现有做法］，
我们的产品［关键功能、必要配套与差异］。
价值主张提示词
请使用已安装的 value-proposition Skill，优化以下愿景与价值主张。

问题探索结果：
［贴入确认后的问题、现有替代方案与关键假设］

七行初稿：
［贴入填好的七行模板］

请先核对目标客户、需求、产品能力、替代方案与主要差异，需要时向我提问。
确认后，用简体中文输出简洁的七行版本，并列出必要的假设和待验证事项。不要把计划中的能力或预期效果写成已实现的事实。

七行模板沿用教材，并参考 Geoffrey Moore 的定位方法。愿景可以描述未来方向，下一步再决定 MVP 先验证哪部分价值。

本步产出七行愿景与价值主张，清楚说明客群、需求、产品与差异。

05

SKILL / mvp

MVP 设计与规划

目标：用最少投入测试关键假设，让早期用户体验核心价值。

按顺序操作

  1. 选定最先解决的问题从前面的结果中，挑出一个优先问题与一个关键假设，说明用户要完成什么任务。
  2. 请 AI 比较做法并缩小范围附上价值主张、时间、人力与工具限制，发送本节提示词。
  3. 确定第一版做什么检查是否能用人工或现有工具试点。写清核心流程、本次范围与暂不做的功能。
  4. 先定标准，再准备试点约定对象、期间、负责人、当前基准与成功标准。试点后据结果决定继续、调整或停止。
MVP = 最小可行产品。核心范围要足以测试关键假设；共享表格和人工服务也可以支持试点。
授信进度示例 · 假设情境，并非已验证成果
问题：同事反复追问申请进度。
假设：能自行查询状态，有助减少追问。
做法：一个部门用共享表格，由专人更新状态。
本次范围：查询申请状态。
暂不做：自动填充、审核校验、跨系统整合。
验证：比较试点前后每件申请的追问次数，并确认同事能否顺利找到状态。
开始前补齐：试点期间、改进目标、负责人和数据更新规则。
MVP 提示词
请使用已安装的 mvp Skill，根据以下情况，帮我确定第一版 MVP 的具体范围。请用简体中文回答。

目标使用者：［谁先试用］
优先问题：［这次先解决什么］
价值主张：［贴入上一步结果］
关键假设：［这次最需要验证什么］
现有做法与工具：［目前如何处理］
时间与人力限制：［可投入的资源］
使用场景：［企业内部使用 / 对外销售］

请比较可选做法，优先考虑人工或现有工具，输出：
1. 第一版只做的一件核心工作
2. 用户完成任务的流程与最简实现方式
3. 本次范围与暂不做的功能
4. 试点对象、期间、负责人及数据更新规则
5. 当前基准、成功标准和反馈方式
6. 什么结果支持继续、调整或停止

对外销售时讨论初始定价；内部使用时聚焦采用意愿与投入。缺少的数据请标为待补，建议的目标请标为待团队确认。

若 AI 给出的范围太大，可继续说：「请缩小到一个部门、一个核心任务，并优先用现有工具。说明这版能验证什么。」

本步产出一份可试点的 MVP 方案，写清对象、核心范围与验证标准。
